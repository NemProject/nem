# Documentation

Congratulations! You found the secret documentation README file, which explains:

* The build process for the new NEM docs site (new as of 2026).
* The tools used.
* The rationale behind some of the decisions.
* How to use these tools in the production on new content pages.

This file is mostly addressed to two audiences:

* Content writers that want to know how to add content and what special tools they have at their disposal.
    Move to the [Content Writers](#content-writers) section.

* Doc-ops guys that need to maintain the docs' pipeline running smoothly.
    Move to the [Doc-ops](#doc-ops) section.

## Content Writers

There are two kinds of documentation pages: original and autogenerated from source code.

### Original Pages

Original pages are created from [Markdown](https://www.markdownguide.org/) text files in the `pages` folder next to this file.
The User Manual, the Textbook and all the tutorials in the Developer Manual are original pages.

A copy of each page exist in each of the supported languages.
For now, these are English and Japanese, and reside in the `pages/en` and `pages/ja` folders.

If you add a new page, remember to add it to the navigation sidebar.
You need to add an entry to the `nav` section in `config/mkdocs.en.yml` and `config/mkdocs.ja.yml`.

You must use Markdown syntax in these files, with some additions brought by the different tools we are using:

* [Basic Markdown syntax](https://www.markdownguide.org/basic-syntax/).
* [Material theme features](https://squidfunk.github.io/mkdocs-material/reference/).
* [Glossary links](https://realtimeprojects.github.io/mkdocs-ezglossary/usage/definition/):

See the [CONTRIBUTING](./CONTRIBUTING.md) guide for more information.

### Autogenerated Reference Pages

Developers usually add comments to their source code in a format that can be read by developers,
but also extracted automatically and used to build exhaustive API reference guides.

This is the method used to generate the reference pages in the NEM Developer Manual,
so tech writers also need to take care of the source code comments in:

* Python: `/_symbol/sdk/python/symbolchain`
* JavaScript: `/_symbol/sdk/javascript/src`
* Java: `/_symbol/sdk/java/src`
* REST: `/openapi`

However, the features available for autogenerated pages are limited to the
[basic Markdown syntax](https://www.markdownguide.org/basic-syntax/).

## Doc-ops

### Dependencies

Can all be installed using `scripts/ci/setup_build.sh` and `scripts/ci/setup_lint.sh`.

### Build Commands

Once all dependencies are installed:

* Run `/scripts/ci/build.sh` from the `mkdocs` folder to generate the static site in the `/docs/` folder.
* Run `/scripts/ci/gh_pages_publish.sh` to publish the site to GitHub pages.

### Build Flow

The docs site is built once per language, using `config/mkdocs.en.yml` and
`config/mkdocs.ja.yml`.
Both language configs inherit shared settings from `config/mkdocs.base.yml`.

Before running a full build, `scripts/ci/setup_build.sh` prepares generated
inputs:

* Installs the MkDocs Node dependencies.
* Builds the TypeScript SDK bindings used by TypeDoc.
* Generates Java SDK Javadocs.
* Builds the OpenAPI YAML file.
* Patches `mkdocs-ezglossary-plugin`.

During each MkDocs build:

* `gen-files` creates navigation placeholder files for generated Python,
    TypeScript, and Java reference pages.
* `typedoc-plugin.py` runs TypeDoc and adds generated TypeScript reference pages
    to the MkDocs file set, unless disabled with `NEM_DOCS_DISABLE_TS=1`.
* `scripts/hooks.py` reads tutorial snippet files from `snippets/devbook`,
    parses snippet markers, and stores the extracted code for tutorial macros.
* `scripts/hooks.py` copies the generated OpenAPI YAML into the REST reference
    folder and loads it so REST shortcut links such as `<get:/node/info>` can be
    resolved.
* `mkdocstrings` generates Python API reference pages.
* `gen_ref_pages_java.py` converts generated Javadoc HTML into MkDocs pages and
    builds the Java reference navigation, unless disabled with
    `NEM_DOCS_DISABLE_JAVA=1`.
* Page markdown hooks rewrite dynamic SDK links, REST shortcut links, WebSocket
    badges, TypeScript reference pages, and tutorial difficulty badges.

The `NEM_DOCS_DISABLE_TS` and `NEM_DOCS_DISABLE_JAVA` flags are useful for
faster local content builds, but they produce many warnings because the
corresponding generated reference pages are missing.

Plugins:

* meta-manager: Adds recursive metadata to Markdown files.
* TypeDoc hook: Uses TypeDoc to generate the TypeScript API docs.
    * TypeDoc is an external TypeScript tool that uses Node.js to run.
    * `typedoc-plugin-markdown` produces Markdown output for MkDocs.
* MkDocStrings: Generates the Python API docs.
    * Uses templates in `templates/mkdocstrings/python/material` to add term definitions.
* gen_files: Plugin that executes Python scripts that can create new files and add them to navigation.
    * `scripts/gen_ref_pages_py.py` creates the Python API files and navigation.
    * `scripts/gen_ref_pages_ts.py` creates the TypeScript navigation.
    * `scripts/gen_ref_pages_java.py` converts Javadoc HTML into Java API files and navigation.
* ezglossary: Plugin that adds tooltips to every term link.
    * Uses templates in `templates/ezglossary`.
* literate-nav: Embeds `links.md` files into navigation.
* macros: Loads reusable macros from `templates/macros`.
* site-urls: Resolves `site:` links used by generated and internal references.
* glightbox: Adds zoom behavior for tutorial screenshots.
* git-revision-date-localized and git-authors: Add page footer metadata, excluding generated reference pages.

Overrides:

These are MkDocs templates to customize the pages.

* `main.html`: Defines the `styles` block that sets colors depending on the section (`userbook`, `devbook` or `textbook`).
    Also loads the Javadoc helper script.
* `partials/source.html`: Empty file to remove the GitHub info on the corner.
* `partials/copyright.html`: Add cookie settings link in the footer.
* `partials/javascripts/content.html`: Script to handle dynamic links that change depending on selected programming language (EXPERIMENTAL).
* `assets/javascripts/javadoc.js`: Adds interactive behavior for generated Javadoc tables.
* `assets/javascripts/katex.js`: Configures math rendering.
* `assets/stylesheets/extra.css`: Contains custom visual styling, including Javadoc styles.
